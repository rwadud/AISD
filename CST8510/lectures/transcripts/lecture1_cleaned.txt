Now ultimately, there are two types of evaluations. One is a reference based evaluation. Reference based means you have some kind of reference data, which is created most likely by humans or by some expert LLM. You are taking the output from your generative AI application and comparing it with that reference data.

Here, you can use some standard metrics. For example, let us stick to LLM evaluations. One of the metrics used is ROUGE. ROUGE stands for Recall Oriented Understudy for Gisting Evaluation. It is basically a metric used even before LLMs came, for summarization purposes. It basically looks at the original text and the summarized text, and looks at n-grams between the original text and the summarized text, and measures the recall. It is recall oriented because it looks at how many n-grams in the reference summary are also present in the generated summary. So that is the ROUGE score. It is the overlap of word sequences between the machine generated summary and the reference summary.

So you have a reference, and in the reference summary, you have a certain number of n-grams. Of those, how many are there in the generated summary? That fraction is the ROUGE score.

The next metric is BLEU. BLEU stands for Bilingual Evaluation Understudy. This was originally developed for machine translation, not summarization. But it can be used in summarization also. It is more like a precision measure. Of the n-grams in the generated summary, how many are there in the reference summary? So BLEU score is more like precision. ROUGE score is more like recall.

Now these scores have a problem. They are looking at exact n-gram match. The problem with that is when a model generates a summary, it might use a slightly different word. It may use a synonym, it may use some other similar word. So these two measures are not useful in that context. They are not sensitive to semantic similarity between words.

So there is another metric people developed called METEOR. METEOR stands for Metric for Evaluation of Translation with Explicit Ordering. It takes care of synonymy and stemming. Even if the reference summary has a word and the generated summary uses a slightly different form, for example "run" versus "running," the first two metrics will not take that into account. But METEOR will take that into account. Or in the generated summary, if they used a similar word, it will recognize that.

Then you can look at other metrics like precision or coverage, how much of the important content from the source is included in the summary.

METEOR is basically a formula. It is an algorithm. You get the results and you can compute them in software. These four metrics are deterministic functions. They do not need an LLM to compute. They just take two inputs and compute using a Python function. There is a formula for doing that. METEOR might need to call some library to get synonyms, like NLTK, the Natural Language Toolkit. That library has functions to compute this. So you do not need an LLM for these metrics.

Then you can look at things like coverage and compression ratio. How much of the original text versus the size of the summary.

Now, the one which is LLM based is BERTScore. BERT is the first language model based on transformers, which was invented by Google. BERT stands for Bidirectional Encoder Representations from Transformers. You can use it to compare semantic similarity. It basically creates a representation, then you look at the similarity between representations. So you can use the BERTScore to compare how semantically similar your generated output is versus the reference summary. So BERTScore uses a model. The previous four do not need a model. These are reference based evaluations.

Now, reference free evaluation. A lot of the time, you will not have a reference. For example, you want to evaluate a customer service chatbot. You want to evaluate things like how helpful is that agent, how fluent is the language, how relevant are the answers. These kinds of questions are subjective. It is difficult to create reference data for these. But you can read the output and figure out how helpful it is, how fluent the English is. In this kind of case, you need to evaluate things like coherence, which is very difficult to create a reference for. You cannot use ROUGE or BLEU scores for that. It is impossible. And even creating a ground truth is not very easy.

So what you can do is use the method of LLM as a judge. You use a more powerful LLM. You give it the input and the output, and say measure along these directions. If you just give that instruction, it will not do a very good job. You have to give some rubrics, how to score, what kind of scoring you want.

Now let us take an example of how to do this using LLM as a judge. What is the LLM as a judge methodology? You use another model, a more powerful one, to evaluate the output generated by the first language model. So it sort of replaces or supplements human evaluation. It is ideal for scaling the evaluation process.

The flow is like this. You already have an AI system that generated output, like the summaries we saw. Then you employ an LLM judge. You provide the LLM judge with the input, also provide the evaluation criteria, and ask what should be the score. Should it be based on zero to 100, zero to one, or some other rubric. And ask the LLM to reason why it arrived at its answer, and provide specific feedback.

Before that, is human evaluation really the gold standard? We always think that human evaluation is the gold standard, which is true to some extent. But there is a recent paper from the University of Edinburgh saying that human evaluation is not always the gold standard. The reason they are saying this is that apparently people found out that when LLMs give a very well written answer which is convincing, people tend to take it as correct. Usually, when LLMs produce output, sometimes it is very well worded, very long, with a lot of details, and the language is usually very assertive. In that case, humans tend to perceive that as more accurate. So human evaluators themselves are getting fooled by the way LLMs speak.

Also, humans have individual preferences and biases. And any human evaluation at enterprise scale is not really cost effective. Because of these reasons, this paper talks about which areas humans get fooled by LLMs. For example, when an LLM says, this is said by a scientist, this is said by somebody, people tend to believe it. You should read this paper. It talks about the areas where humans get fooled.

For us, we need to just understand that usually an LLM will be very assertive and it gives very complex logic explaining why it is doing something, and people will believe that.

Also, using LLM as a judge gives you scalability. You can evaluate, for example, a thousand summaries in a day, which is not possible with humans. A human being per hour, you have to pay maybe $100, whereas if you are using an LLM, you pay maybe cents or maximum one or two dollars. So it is more scalable. A lot more evaluations get done in a day, and it is a lot cheaper.

Not only that, if you train human evaluators in one domain, like healthcare, and tomorrow you want to evaluate something in finance, it will be very difficult to retrain them because people develop expertise over a period of time. It is difficult to train them to adapt to another domain. Whereas LLMs, you can easily adjust or provide them with a different kind of knowledge source. So there is a lot of flexibility in using LLM as a judge for domain adaptation.

And for very complex scenarios, like healthcare, where you need to evaluate a lot more scenarios to come up with a decision, or you need to read through a lot more complex knowledge like legal matters, an LLM judge sometimes will help because it can get into those details if you prompt it correctly. So it may be more useful than a human judge in some cases. It is not very clear cut, but that is what the research suggests.

So there are some example scenarios for using LLM as a judge. For example, evaluating customer service response generation. You designed a chatbot for customer service. You are a company and you want to see if the responses generated by the chatbot are things like, is it friendly. Does the response address the customer's underlying concern? Is the tone of the response professional, or is it talking like a casual person? People do not like that. Does it handle cultural nuances? For example, you develop a chatbot in the US and deploy it in the Middle East or Asia. There are a lot of cultural aspects in how people talk to each other. And does it likely lead to customer satisfaction at the end? These are subjective questions. For these kinds of things, LLM as a judge is a very good option.

Now, with an LLM as a judge approach, there are three types of evaluation. One is single output scoring with a reference. Two is single output scoring without a reference. Three is pairwise comparison, where you take two outputs and ask which one is better.

For single output scoring without a reference, the LLM is tasked with assigning scores based on predefined criteria. For example, you have an output: "I understand your frustration with the delayed delivery. Our team is working on your order and you will receive a tracking number within 24 hours." This is the output generated by your chatbot agent for a customer service application. Now you want to evaluate it. You give criteria to the LLM. If the response is unprofessional or dismissive, give a score of one. If it is professional but provides an incomplete solution, give a score of two. If it is professional, empathetic, and provides a clear resolution, give a score of three.

Always, do not tell LLMs to give a score between zero to 100. It does not understand that. It does not have a clear way to figure out if something is 50 or 73. Always give a discrete scale and for each value of the scale, give criteria, just like a rubric. That is what it should be. So here, for example, there are three values: one, two, or three. And when it should give one, when it should give two, when it should give three, you have to clearly specify in the prompt.

This is particularly useful for straightforward evaluation where the quality of output can be assessed without any reference.

Now you can have a slightly more detailed evaluation: single output scoring with a reference. You provide the reference also, and ask it to compare with the reference and give an answer. For example, the LLM produced this output: "The new environmental law requires companies to reduce carbon emissions by 30% by 2030." Let us say the question was, what does the Environmental Protection Act of 2024 mandate? Now this seems like a good answer, but the actual reference answer is slightly different. The reference says: "The Environmental Protection Act of 2024 mandates a 30% reduction in carbon emissions for companies with over 500 employees by 2030, with annual progress reports required."

What is happening is that the generated answer is missing the point that the requirement only applies to companies with over 500 employees. So you give your scoring criteria as a rubric. If it contains inaccurate information, give a score of one. Partially accurate but missing key details, give a two. Accurate but incomplete, give a three. Complete and accurate match with the reference, give a four. What would be the answer here? It missed a key detail about the company size requirement. So it would probably get a two or three depending on how the LLM judges it. It captures the main point but is missing the company size requirement. This is single output scoring with a reference.

The third type is pairwise comparison. For example, there are two product descriptions provided by a chatbot. One is: "Our wireless headphones offer 20 hour battery life and noise cancellation." The other response is: "Experience uninterrupted music with our wireless headphones featuring 20 hour battery life, advanced noise cancellation, and comfortable memory foam ear cushions." Obviously, the second one is a much better response. If you ask the LLM to compare, it should say the second response is better because it covers more features and benefits while maintaining clarity and engagement. Pairwise comparison is particularly useful for comparative scenarios.

So here is a summary of when to use each approach. For simple, independent tasks, single output scoring without a reference is useful. For complex tasks needing more context or reasoning, you can use single output scoring with a reference. For relative quality assessment, you can use pairwise comparison.

In terms of scalability, single output scoring scales much better. Pairwise comparison scales less well because you have to compare many pairs. If you have two sets with a large number of outputs, the number of pairs grows exponentially. In terms of implementation, single output scoring is easier to implement. Pairwise comparison is more difficult. In terms of consistency, pairwise comparison gives more consistent results. In terms of explainability, pairwise comparison is also better because you get better explanations. In terms of impact of LLM updates, pairwise comparison will be less affected because it is comparing two things. If you change the LLM, it will be more consistent. Whereas if you ask it to produce a score directly, the scores might shift.

So use LLM as a judge when the output is primarily subjective, evaluation requires understanding of context or nuances, multiple aspects need to be evaluated together, or traditional metrics cannot capture important qualitative aspects. When you have ground truth and you want things like accuracy, precision, and recall, you might as well use deterministic metrics.
