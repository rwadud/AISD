So G-Eval. G-Eval is a framework from Microsoft Research. So what they did was that they extended the LLM as a judge method. They kind of standardized it. So the idea is this. Remember, earlier when we did the LLM as a judge, for example, let us say you have a summary, and you want to evaluate the summary on a scale of one to three. So one is this, two is this, three is this. For example, one is the summary is coherent but not complete, two is coherent and complete, like that we give some rubric. So it will give you a score of one, two, three, right? But you probably want a kind of numerical score, not just an integer. Also, every time you want to define the evaluation steps.

So what does G-Eval do? Let us say, for example, you give it a summary that was written for a news article. Your task is to rate the summary on some kind of scale. You give the evaluation criteria. Now, what this framework does additionally is that it automatically creates a chain of thought steps for the LLM. It will say, think step by step, then do this, do this, do that. It will create that chain of thought steps. That is one thing.

So secondly, for example, in this case, the task is to rate the summary. And you provide the rubric. Then you get the evaluation steps. For example: first, read the news article and identify the main topic and three key points. Second, read the summary and compare it to the news article. Check whether the summary covers the main topic and three key points, and if it presents them in a clear order. Step three, based on this, assign a score on a scale of one to ten, where one is the lowest and ten is the highest. So this chain of thought evaluation is provided by the framework.

The other thing G-Eval does is that it takes the output score, whether it is one, four, five, whatever. When the LLM outputs "one," it is not always just one. In the sense that if you have temperature not set to zero, it actually produces all the tokens but with certain probabilities. That is how generative models work for next token prediction. So one is actually the maximum probability token. But it also has tokens for two, three, four, five, with much lower probabilities. That is why it is giving one, it means that it is producing the token "one" with the highest probability.

So what this framework does is that when you query the LLM, you can actually get all the tokens with their probabilities. When you send the API request, you can get the token probability for each token. Then the G-Eval framework takes each score as a token, multiplies it by the token probability, and takes a weighted average. So you get a continuous score. Why are you doing this? This gives a more robust evaluation, because you do not know what is the confidence by which the LLM is saying this score is one. Maybe if you run that 10 times with temperature at 0.2 or something, maybe eight times it will give one, one time maybe two, another time maybe three. You do not know. So to get a sense of the confidence value of the LLM in giving the score, this weighted average metric is useful. So this is what G-Eval proposes on top of LLM as a judge.

Then there is another framework called RAGAS. So there is another paper, I think from a UK university. The RAGAS framework came up with three metrics for evaluating RAG applications. The first is faithfulness. Faithfulness measures whether the information generated in the answer can be supported by the context. So it basically checks for hallucination. There is a context retrieved from the vector database and there is a response generated by the LLM. So is there any hallucination happening by the LLM? It will compare the response with the context.

One thing to note is that the order matters. In LLMs, technically the order of the context affects the output. The beginning of the context tends to be given more importance. So if the context is very long, relevant information might get lost in the middle. You might want to change the order or make the context smaller.

So what faithfulness does is it takes each statement from the final answer. It takes each statement and verifies whether the statement is present in the context. Whether it is supported by the context. Then it takes the fraction of statements which are supported. So the LLM judge extracts individual statements from the generated answer, and for each statement, it verifies it against the context. Then it calculates the fraction: the number of supported statements divided by the total number of statements in the response. For example, if your summary has five sentences, and out of five sentences, four sentences are verified against the context, then four out of five is your faithfulness score.

The second metric is answer relevance. Answer relevance measures whether the generated response directly addresses the question. So this is slightly different. You want to compare the response to the original question. It is not about hallucination, but whether the answer is relevant to what was asked. So what it does is it takes the answer and generates possible questions that could have produced this answer. So it does an inverse process. Take the final answer and generate possible questions for that answer. Then it calculates the similarity between each of those generated questions and the original question. That average similarity is the answer relevance score. So if your answer is relevant, then most of the generated questions will be very similar to the original question.

Then the third metric is context precision. Context precision measures how relevant the retrieved context is for answering the question. So here, it takes the context itself. You break the context into sentences, and you take each sentence in the context and see if the sentence is relevant for answering the question. Maybe the context has ten sentences, and out of those, only one is relevant for answering the question. So this is something like a precision metric. This is about retrieval quality.

So one question is, what if the LLM generates the correct answer anyway, even if the context is not relevant? So the answer is relevant and useful, but it is not derived from the context. It is generated from the LLM's own knowledge. That case is captured by the faithfulness metric. These metrics are used in situations where the LLM does not know the context. For example, your company's internal documents. In those cases, if the LLM generates some answers, that could be hallucination. But if it generates a correct answer, then we know that it is using the context. Now, the remaining sentences in the context which are not mentioned in the answer, they are not very useful for that query. So your context retrieval is generating noise. How do you fix it? You either return fewer results or you re-vectorize so that you get better context. So this metric is about evaluating the retrieval quality.
