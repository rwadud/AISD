Containers came because people faced a lot of challenges. They could not test everything in their development environment. They would hand things off to production engineers, and when they tried to deploy in their production environments, there were issues. There were many reasons for this deployment difficulty, and people wanted to standardize the basic system. What people came up with was this idea of a Docker container. A Docker container is a lightweight, standalone executable package.

They started to miniaturize everything. Earlier, everybody was running all applications on big servers like IBM servers, HP servers, and Sun servers. Companies would have all their applications running on those. Once development evolved and cloud came along with VMware, all these things could be virtualized. They started virtual machines. Some part of the application would run on a virtual machine. Virtual machines are small, built up, shut down, and provisioned.

Then came microservice architecture. Each application would have some kind of machine that could run it. Then they tried to miniaturize further. They said, you don't need so many things to run one application. One application may need only a few libraries and some compute components. So they tried to package only that much. If you take a Python application, for example, all those libraries required to run the Python code and the dependencies required, you package it into a smaller unit. That's the container. A container is a standalone executable software package that includes all the libraries, code, and runtime, and it runs that application.

Another problem with Python: Python came with open-source libraries. There are so many libraries available, and people started using them, and these libraries come in different versions. When your application runs, for example, with NumPy or Pandas, there are certain versions. A new application may not be compatible with them. So there are always conflicts. This conflict management became huge because of version overlapping. That's how Docker containers came about, because each container can have its own version. This Docker container is a kind of software environment ensuring that what I develop and what works for me always works. That software always behaves the same way.

Another thing, as I mentioned at the beginning: you can take this image from your laptop or development environment and give it to production engineers, and they can test it on the production environment. It abstracts the topic and makes it easy to move your images from one environment to another, and it runs without any confusion. That's the biggest advantage of Docker.

Schedulers can handle one workflow with different entities.
